# Contributing

Norevify is a live, monetized product (see [LICENSE](LICENSE) — proprietary,
all rights reserved). This repository is public for **portfolio review**,
not as an open-source project.

## What's welcome

- **Bugs** — anything broken or behaving wrong. A repro-steps +
  expected/actual + severity write-up (see the
  [issue template](.github/ISSUE_TEMPLATE/issue_report.md) and the existing
  closed issues for examples) is appreciated but not required.
- **UX findings** — something that works as coded but is confusing,
  ambiguous, or just awkward to use. These are valued as much as bugs — most
  of the closed issues in this repo are exactly this, found by walking
  through real user flows.
- **Feature ideas / product feedback** — use the
  [feature request template](.github/ISSUE_TEMPLATE/feature_request.md).
  Ideas are triaged against the product roadmap and may be declined; that's
  normal for a single-owner commercial product, not a reflection on the idea.
- **Questions** — about the codebase, the test suite, the architecture,
  anything. Open a blank issue.

[GitHub Issues](../../issues) is the home for all of the above.

## What isn't accepted

Pull requests and code contributions. The license is proprietary and the
product is commercial, so reused, modified, or redistributed code isn't
licensed for that use — see [LICENSE](LICENSE). Reading and forking to study
the code is fine. An unsolicited PR will be closed with thanks and, if the
underlying finding is good, turned into an issue instead.

Want to run it locally to poke around? See
[Quick start](README.md#quick-start) in the README.

## Security

**Security issues** → see [SECURITY.md](SECURITY.md), do not open a public
issue.

## Hiring / portfolio review

If you're here evaluating the codebase or test suite as part of a hiring
process or similar, feel free to reach out — contact details are in the
[README](README.md#author).

Participation in issues and discussions is governed by the
[Code of Conduct](CODE_OF_CONDUCT.md).
